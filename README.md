## v13 · 지도 초기화 시점과 가로 넘침 수정

- 미표시 원인: 현재 NAVER SDK(확인 응답 3.10.1)의 준비 콜백은 공개 `window.naver.maps` 내보내기보다 먼저 실행될 수 있습니다. 기존 로더는 그 안에서 네임스페이스를 읽고 `null`로 Promise를 완료해 정상 SDK가 내려와도 지도를 생성하지 않았습니다. URL `callback`과 전역 `serenityMapsReady`를 제거하고, 코어 스크립트 실행이 끝난 뒤의 네이티브 `script.onload`에서 네임스페이스를 읽도록 교체했습니다. Client ID·클라우드 API·허용 URL 설정은 바꾸지 않았습니다.
- 넘침 원인: 실제 브라우저에서 지도 컨테이너는 448.69px인데 내부 Grid 트랙/안내 영역은 527px이었습니다. `min-height:310px`와 `aspect-ratio:1.7`의 전이 최소 폭 계산 때문입니다. `.map-stage`의 트랙을 `minmax(0,1fr)`로 명시하고 지도/안내 요소에 `min-width:0; max-width:100%`를 적용했습니다. UI 디자인 스킬 기준으로 기존 여백·문구·등장 애니메이션을 유지하며, 고정 높이 추가·잘라 숨기기·별도 크기 관찰자는 넣지 않았습니다.
- 코드 검증: JS 문법, 빌드, 세 언어 32개 문서, 기존 지도/가로 갤러리 테스트, 네임스페이스가 SDK 실행 중에는 없고 `load` 직전에 생기는 순서의 회귀 검사, 축소 가능한 Grid 규칙, `git diff --check` 통과.
- 이번에는 사용자 승인 후 실제 인앱 브라우저 검사를 진행했습니다. 메인에서 지도 타일 표시와 송도 전환을 확인했습니다. 기본 화면에서는 컨테이너·지도 폭이 448.69px로 일치했고, 1280×800 설정에서는 667.25px로 함께 변경됐습니다. 390×844 설정(스크롤바 제외 콘텐츠 폭 375px)에서 메인과 상세 4곳 모두 지도 폭 327px, 페이지 가로 넘침 없음, 실제 타일 표시를 확인했습니다. 한국어 전환과 송도 상세 중국어 전환/PC 폭 변경(566.94px 일치)도 확인했습니다. 임시 뷰포트는 해제하고 원래 영어 설정으로 복구했습니다. 실제 휴대폰·중국 현지 네트워크·GitHub 배포본은 검증 대상이 아닙니다.

## v12 · 네이버 지도만 표시

메인·상세 4곳에서 OpenStreetMap iframe·외부 버튼·주소 생성·대체 로딩 처리를 제거했습니다. 지도 버튼은 네이버 지도 링크 하나만 남습니다. 인증/SDK 로딩 실패 또는 JS 미사용 시 다른 지도를 호출하지 않고 로컬 안내 문구와 네이버 지도 링크를 표시합니다. 기존 Client ID 값·주변 지역 좌표·지도 애니메이션은 유지하며, 모든 공용 자산 참조는 `v=12`입니다. 기존 `mapUrls()`는 단일 네이버 링크를 만드는 `naverMapUrl()`로 단순화하고, 미사용 `mapOpen` 번역·`span` 데이터·다중 링크 래퍼도 제거했습니다.

검증: JS 문법 검사, 빌드, 세 언어 32개 문서 검사, 네이버 링크 단일 노출 및 OpenStreetMap 코드/요청 주소 없음, SDK 실패 시 로컬 안내 표시 테스트 대역 검사, `git diff --check`. 브라우저 자동 조작·실제 지도 인증 확인·git push·배포는 하지 않았습니다.

## v10 · 네이버 지도 연결 준비와 가로 사진 재생

- 메인·상세 4곳 모두 같은 `mapPanel()` / `syncNaverMap()`을 사용합니다. `map-config.js`의 `clientId`는 **빈 상태**이며, 현재는 기존 OpenStreetMap이 표시됩니다. 실제 NAVER 인증·지도 타일 로딩은 아직 검증하지 않았습니다.
- Client ID를 입력하면 NAVER Maps 브라우저 SDK를 한 번 불러옵니다. 숙소 선택 시 지도 인스턴스를 다시 만들지 않고 중심만 변경합니다. 언어 변경으로 DOM이 교체되면 이전 지도는 정리합니다. SDK 로딩·인증·초기화 실패 시 OpenStreetMap을 유지하거나 복원합니다. 지도 타일 서버만 차단되는 경우까지 자동 감지하는 것은 아니므로 외부 지도 링크도 항상 제공합니다.
- 위치는 기존 **주변 지역 샘플**입니다. 정확한 숙소 핀은 추가하지 않았습니다. 지도 지명은 해외 고객을 고려해 영어로 고정하며, 페이지 소개·접근성 제목·버튼은 기존 세 언어 전환을 유지합니다. 마우스 휠로 페이지를 내릴 때 지도가 확대되지 않도록 했습니다.
- 지도는 화면 높이 85% 선에서 아래 64px→제자리로 1.2초 동안 이동하고, 같은 선을 위로 되짚으면 되돌아갑니다. UI 디자인 스킬에 따라 지도 글자를 흐리거나 확대하지 않습니다. 기존 Grid 안에서 안쪽 패널만 움직이며 고정 좌표 배치를 추가하지 않았습니다.
- 기존에는 레일 전체가 세로로 진입하면 가로로 보이지 않는 사진까지 재생이 끝났습니다. 이제 공용 스크롤 제어기의 기존 이벤트를 재사용해, 사진이 가로 영역에 20% 이상 들어오고 로딩된 뒤 펼침·확대 해제 효과를 적용합니다. 완전히 밖으로 나간 사진은 초기 상태로 돌아가고 재진입 시 다시 재생합니다. 새 라이브러리·별도 스크롤 리스너·타이머는 추가하지 않았습니다.
- `prefers-reduced-motion`, JS 없는 정적 표시, 스크롤바 숨김, 독립 상세 페이지, Coming Soon, Airbnb 예약 링크는 유지합니다. 공용 자산 버전은 모두 `v=10`으로 맞췄습니다.

검증: `node --check app.js`, `node --check content.js`, `node --check map-config.js`, `node --check build.cjs`, `node build.cjs`, `node check.cjs`, `git diff --check`. 3개 언어·32개 문서, 가로 탐색/이미지 로드/재진입/동작 줄이기/정리, 지도 설정 없음/성공/실패/중복 요청/언어 DOM 교체를 검사했습니다. 지도 SDK는 테스트 대역으로 실행해 실제 API 요청·과금은 발생시키지 않았습니다. **이번 v10은 브라우저 자동 조작·화면 검사를 수행하지 않았습니다.**

### NAVER 설정과 GitHub Pages 보안

1. NAVER Cloud의 Maps Application을 준비하고, 이 사이트에 필요한 **Dynamic Map**을 선택합니다. 주소 검색/경로 API와 Client Secret은 현재 구현에 필요하지 않습니다.
2. Web 서비스 URL에 본인의 실제 사이트 주소를 등록하고 콘솔에서 허용하는 가장 좁은 범위로 제한합니다. GitHub Pages는 본인 계정의 주소를 기준으로 인증을 확인하세요. 공용 `github.io` 전체를 허용하는 방식으로 인증 실패를 해결하지 마세요. 공유 도메인에서 원하는 제한이 되지 않으면 전용 도메인 사용 또는 NAVER 측 확인이 필요합니다. 개발용 로컬 URL은 별도 애플리케이션으로 분리하거나 개발 종료 후 제거하는 것을 권장합니다.
3. 일별·월별 **이용 한도와 임계치 알림**을 설정하고 대표 계정/무료 제공량/과금 조건을 확인합니다. 도메인 제한만으로 오남용·비용 위험이 완전히 사라지는 것은 아닙니다.
4. `map-config.js`의 빈 `clientId`에 **브라우저용 Client ID만** 입력합니다. Client Secret·계정 API Secret을 넣거나 공유하지 마세요. 실제 ID 입력 및 배포는 사용자 준비·승인 후 진행합니다.
5. 허용한 실제 URL에서 메인/상세·지역 변경·모바일 크기 변경·인증 오류·지도 타일과 NAVER 로고/출처 표시를 확인해야 합니다. 중국 현지 네트워크에서의 가용성도 별도 확인이 필요합니다.

Client ID는 공식 JS SDK의 `ncpKeyId` 쿼리로 브라우저에 전달되므로 소스/네트워크에서 확인할 수 있습니다. GitHub Actions Secret이나 빌드 환경변수로 주입해도 최종 프런트엔드 값은 숨겨지지 않습니다. 비공개 저장소로 바꾸는 것만으로도 해결되지 않습니다. **Client Secret은 이 방식과 다르며, 프런트엔드나 공개 Git 저장소에 절대 포함하면 안 됩니다.**

공식 근거: [JS SDK 로딩·인증 오류 처리](https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html), [Application 등록·이용 한도·알림](https://guide.ncloud-docs.com/docs/application-maps-app-vpc), [영문 지도 설정](https://navermaps.github.io/maps.js.ncp/docs/tutorial-Language.html).

## v9 · 페이드 대신 시간 기반 펼침과 역재생

v8의 스크롤 진행률 기반 효과와 `title/copy/frame/photo-unfold` 키프레임을 제거했습니다. UI 디자인 스킬의 기준은 **기존 레이아웃·문구 유지, 선명한 사진, 줄별 제목, 프레임 확장과 내부 확대의 시간차**입니다. 별도 라이브러리 없이 브라우저 기본 관찰자와 CSS transition으로 구현합니다.

- 시작: 바깥 레이아웃 영역의 윗변이 화면 높이 85%를 통과하면 재생합니다. 이후 스크롤을 멈춰도 끝까지 진행합니다. 위로 스크롤해 같은 선을 되짚으면 역방향으로 돌아가며, 다시 내려오면 재생합니다. 화면 위로 지나간 내용은 완료 상태를 유지합니다.
- 제목: 불투명도 변화 없이 줄마다 아래에서 1.05초 동안 올라옵니다. 다음 줄은 110ms 뒤에 시작합니다. 본문은 선명한 상태에서 32px 이동합니다.
- 사진: 양옆 11%씩 좁혀진 프레임이 1.15초 동안 펼쳐지고, 내부의 122% 확대는 120ms 뒤부터 1.45초에 걸쳐 풀립니다. 사진은 초기·역재생 중에도 완전히 숨겨지지 않습니다. 기존 대표 사진의 기본 크롭은 유지합니다.
- 카드: 크기 88%→100%, 카드별 최대 260ms 시간차를 사용합니다. 왼쪽 가장자리는 움직이지 않아 기존 좌우 버튼의 위치 계산을 유지합니다. 장점은 45px 이동과 90ms씩의 시간차를 사용합니다.
- 공용 처리: 움직이지 않는 바깥 영역을 관찰하고 안쪽만 움직입니다. 상세 이야기 사진에는 확대가 캡션을 침범하지 않도록 일반 흐름의 프레임 하나를 추가했습니다. 갤러리·숙소 레일의 스크롤바 숨김과 기본 스크롤 탐색은 유지합니다. 대표 숙소 교체 시 새 영역만 관찰하고, 언어 변경·동작 줄이기 변경 시 이전 관찰자를 정리합니다.
- 안전성: JS·관찰 기능이 없거나 동작 줄이기가 켜진 경우, 인쇄에서는 정적 콘텐츠를 표시합니다. 일반 스크롤 효과에는 opacity·blur를 사용하지 않습니다. 대문 슬라이드와 사용자가 버튼으로 넘기는 숙소 전환은 별도 기존 효과입니다.

검증: `node --check app.js`, `node --check build.cjs`, `node build.cjs`, `node check.cjs`, `git diff --check`. 세 언어·32개 문서 검사와 실제 공용 제어 함수의 시작/역방향/재진입/교체/크기 변경/정적 대체 실행 검사를 통과했습니다. 이는 브라우저 렌더링 검사와 별개입니다.

실제 인앱 브라우저 PC 1280×720에서 메인 제목의 정지 중 재생 완료와 역재생, 사진 프레임·확대의 정지 중 완료와 되감기, 숙소 교체 후 재등록, 카드별 시간차를 확인했습니다. 미아 201 갤러리도 정지 중 완료·역재생·사진 4장 로딩·불투명도 1·스크롤바 숨김을 확인했습니다. 390×844 화면에서 사진 4장과 방향키 이동(691→943px), 가로 넘침 없음, 갤러리 높이 유지(402px)를 확인했습니다. 실제 휴대폰·다른 브라우저와 다른 세 상세 화면은 전수 검사하지 않았습니다.

## v8 · 눈에 보이는 모션과 실제 스크롤 검증

v7을 일반 모션 환경의 실제 브라우저에서 확인했습니다. CSS 기능은 지원되고 효과도 적용됐지만, 36px 이동·3% 크기 변화가 페이지 스크롤에 묻히는 문제가 있었습니다. 이번에는 디자인 스킬의 기준에 따라 **제목 줄별 등장 / 본문 페이드 / 사진 프레임·내부 확대**로 역할을 나누고, 약한 공용 효과와 중복 사진 깊이 효과를 교체했습니다.

- 제목: 기존 문구와 줄바꿈을 공용 `heading()`으로 출력합니다. 제목 줄만 감싸는 일반 흐름의 span으로 아래에서 펼쳐지는 효과를 만들고, 둘째 줄은 5vh 늦게 진행합니다. 고정 높이·절대 좌표·텍스트 복제는 사용하지 않습니다.
- 본문: 64px 이동과 24%→100% 페이드를 복원했습니다. 장점 카드는 순번에 따라 시작 지점만 조금씩 다릅니다.
- 사진: 내부 확대 118%→100%, 큰 프레임 93%→100% 및 64px 이동을 사용합니다. 사진 자체의 불투명도는 항상 1이며, 스크롤용 숨김 마스크를 쓰지 않습니다. 기존 대표 사진 기본 크롭(108%)과 호버·수동 숙소 전환은 유지합니다.
- 상세 갤러리: 사진마다 안정적인 확대 프레임(`.gallery-photo`)을 추가했습니다. 세로 진행률은 레일의 페이지 내 위치에서 얻고 가로 스크롤 위치와는 분리됩니다. 사진을 넘겨도 레일 높이가 증가하거나 세로 스크롤바가 생기지 않게 했습니다.
- 진행: 첫 제목 줄은 85%→50%, 둘째 줄과 사진은 80%→45% / 85%→45% 화면 구간에서 완료됩니다. 시간을 기다려 자동 완료되는 모션이 아니라 스크롤을 멈추면 유지하고 해당 구간을 되짚으면 역방향으로 움직입니다. 필요한 CSS 기능이 없는 브라우저, 동작 줄이기, 인쇄에서는 이 스크롤 모션이 적용되지 않습니다.
- 구조: 관찰자·스크롤 이벤트·라이브러리를 추가하지 않고 브라우저 기본 타임라인을 사용합니다. 사진 프레임과 제목을 기준으로 하위 요소를 움직입니다. [MDN named view timeline](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/view-timeline-name).

확인한 범위: 코드 검사와 세 언어·32개 생성 문서 검사 통과. 실제 인앱 브라우저 PC 1280×720에서 메인 제목의 줄별 진행, 정지 중 상태 유지, 사진 확대 완료 후 되감기를 확인했습니다. 미아 201 갤러리에서 확대 역진행, 좌우 버튼, 네 사진 로딩과 불투명도 1, 스크롤바 숨김을 확인했습니다. 390×844 좁은 화면에서 갤러리 방향키 이동(691→943px), 페이지 가로 넘침 없음, 사진 표시를 확인했습니다. 실제 휴대폰·모든 브라우저·다른 세 상세 페이지의 화면 전수 검사는 하지 않았습니다.

## v7 · 스크롤에 연결되는 등장 효과

일회성 `IntersectionObserver` 등장 처리와 0.85~1.1초 재생·시간차 지연·정리 함수를 제거하고, 공용 CSS 스크롤 타임라인으로 교체했습니다. 레이아웃·사진·문구·예약 링크는 유지합니다.

- 시작/완료: 요소의 **레이아웃상 윗변**이 화면 높이의 85% 지점에서 시작하고 45% 지점에서 완료됩니다. `animation-range: cover 15vh cover 55vh`로 요소 높이와 무관한 40vh 진행 구간을 사용합니다. 화면 진입 직후 효과가 끝나지 않도록 선형 진행을 적용했습니다.
- 정지/되감기: 시간이 아니라 스크롤 위치가 진행률을 결정합니다. 정지하면 유지되고 위로 스크롤해 해당 구간을 되짚으면 역방향으로 돌아갑니다. 완료 지점을 지나 화면 상단으로 올라간 내용은 최종 상태를 유지합니다.
- 사진 안전성: 위치·크기만 움직이고 불투명도·마스크는 변경하지 않습니다. 큰 사진은 97%→100%, 일반 내용은 최대 36px의 이동을 사용합니다. 가로 사진 투어와 숙소 목록은 레일 전체를 움직여 세로 진입 효과와 가로 탐색을 분리합니다. 갤러리 부모의 `overflow: hidden`은 `clip`으로 교체해 비스크롤 부모가 타임라인을 가로채지 않게 했습니다.
- 공통 적용: 메인과 네 상세 페이지의 `.reveal`, 숙소 레일, 지도 소개, 갤러리 레일에 적용됩니다. 언어·대표 숙소를 변경해 생성되는 요소도 별도 관찰 재등록 없이 같은 CSS를 사용합니다. 지역 카드에 중복 적용되던 별도 등장 모션을 제거했습니다. 대문 재생·숙소 수동 전환·호버 효과는 유지합니다.
- 접근성/호환성: ‘동작 줄이기’와 인쇄에서는 이 모션을 사용하지 않습니다. 필요한 CSS 타임라인 기능이 없는 브라우저에서는 사진과 내용을 정적으로 표시합니다. 별도 패키지·스크롤 이벤트·타이머를 추가하지 않았습니다. [MDN animation-range](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-range).
- 캐시: 메인과 네 상세 페이지의 공용 CSS/JS 참조를 `v=7`로 변경했습니다. GitHub Pages 반영·git push·배포는 하지 않았으므로, 공개 사이트에는 별도 반영이 필요합니다.

검증 범위: `node --check app.js`, `node build.cjs`, `node check.cjs`의 코드·생성 문서 검사. 공통 타임라인 구간, 일회성 처리 제거, 사진 숨김 없음, 가로 스크롤·스크롤바 숨김, 상세 공통 파일 버전을 검사합니다. 이번 변경은 실제 브라우저 자동 조작 검사를 수행하지 않으며, 체감 속도·역방향 스크롤·모바일은 미리보기에서 직접 확인해야 합니다.

## 이번 방향

UI 디자인 스킬 `design-first-ui-prompting`을 적용해, 세러니티가 운영하는 공간의 사진·이야기·동네가 중심이 되는 숙소 포트폴리오로 정리했습니다.

- **메인 4영역:** 대문 사진 → 호스트 소개·숙소 포트폴리오·위치 지도 → 숙소 장점 5가지 → 지역 명소 안내.
- **대문:** 사용자 숙소의 실제 사진, 큰 세리프 타이포, 7.2초 간격 크로스페이드, 확대 모션, 이전·다음·자동 재생 정지 버튼.
- **숙소 소개:** 두 줄 목록형 그리드를 제거했습니다. 대표 사진 한 장, 공간별 이야기, 인원·편의시설을 보여주는 큰 소개 영역에서 이전·다음 숙소를 살펴볼 수 있습니다. 대표 사진은 PC·모바일 모두 보조 사진 없이 사진 영역 전체를 사용합니다. 그 아래에는 PC 3개 / 태블릿 2개 / 모바일 다음 카드 일부가 보이는 가로 썸네일 탐색을 배치했습니다. 썸네일은 독립 상세 페이지로 연결되며 Coming Soon은 세 번째 카드이고 예약 링크가 없습니다.
- **운영 브랜드:** 대문과 숙소 소개에 세러니티가 운영하는 집이라는 설명을 넣었습니다. 프라이빗 욕조·햇살 드는 다이닝·밝은 거실·바다 전망 등 실제 공간마다 다른 장면을 소개합니다. 설립 연도·디자이너·호스트 이력 등 미확인 브랜드 이야기는 만들지 않았습니다.
- **상세:** 기존 모달을 완전히 제거했습니다. 각 숙소는 주소가 다른 실제 HTML 페이지입니다. 대문 → 인원·침실·침대·욕실 → 공간 이야기·침대 구성 → 가로 사진 투어 → 편의시설 → 주변 안내·체크인 → Airbnb 예약으로 연결됩니다.
- **모션:** 대문 제목 등장, 그룹별 스크롤 이동, 숙소 전환 시 사진 펼침·확대, 지원 브라우저의 스크롤 깊이·페이지 전환. 스크롤 등장 효과를 기다리는 동안 사진을 숨기지 않으며, 시스템의 동작 줄이기 설정을 존중합니다.
- **지역 카드:** 이미지에 호버하거나 키보드 포커스를 주면 소개 문구와 그라데이션이 걷히고 사진·탐색 안내가 드러납니다. 마우스 호버 효과는 정밀 포인터 환경에만 적용되며 터치에서는 기본 소개를 유지합니다. 이미지 바깥에도 도시명을 표시해 맥락이 사라지지 않습니다.
- **지도:** 메인에서 숙소별로 주변 지역 샘플 지도를 선택할 수 있습니다. 숙소 소개를 넘기면 해당 지도도 연결됩니다. 상세 페이지에서는 기존 관광지 사진을 해당 숙소 주변의 샘플 지도로 교체했습니다.
- **언어:** 영어 기본, 한국어·중국어 간체 지원. 선택 언어만 로컬에 저장합니다.

## 수정 및 숙소 추가

원본은 `content.js`, `app.js`, `styles.css`, `build.cjs`입니다. `index.html`과 `stays/*.html`은 생성 결과이므로 직접 수정하면 다음 생성 때 덮어써집니다. 지도와 번역은 `content.js`, 공유 사진 탐색과 템플릿은 `app.js`에 있습니다.

1. `content.js`의 `stays` 배열에 숙소를 추가합니다. 배열 순서가 목록 순서입니다. 각 문구는 `[영어, 한국어, 중국어 간체]` 형식입니다.
2. 운영 숙소는 `status: "open"`과 정확한 Airbnb `listingId`, 확인한 정원·침실·침대·욕실, 사진 경로 등을 입력합니다. `signature.title`과 `signature.text`는 메인에서 소개할 해당 공간만의 장면입니다. `map`은 지도 설정입니다. `id`에는 영문 소문자·숫자·하이픈만 사용하세요.
3. 오픈 예정은 기존 `busan-next`와 같이 `status: "coming-soon"`을 사용하며 예약 정보와 미확정 날짜를 넣지 않습니다. 현재 예고 카드 문구·이미지는 부산 신규 숙소용입니다. 다른 도시의 오픈 예정 숙소를 추가한다면 해당 문구·이미지도 함께 확장해야 합니다.
4. 사진 파일을 `assets`에 넣고 아래 명령으로 HTML을 다시 생성합니다.

```sh
node build.cjs
node check.cjs
```

운영 숙소를 추가하면 카드와 별도 상세 HTML이 함께 생성됩니다. 실행 중인 페이지에는 자동 새로고침 기능이 없으므로 수정 후 새로고침하세요. 숙소를 삭제·이름 변경한 경우 이전에 생성된 상세 파일을 자동 삭제하지 않으므로, 공개 전 오래된 파일의 유지 여부를 사람이 확인해야 합니다.

## 지도 샘플과 교체 위치

사용자가 정확한 위치를 확인하기 어려우면 샘플로 진행해도 된다고 허용했습니다. 따라서 지도는 **숙소의 정확한 위치를 확인한 결과가 아닙니다**. 미아·수유 / 연신내 / 송도 주변 지역을 보여주는 데모이며, 정확한 숙소 핀이나 주소를 넣지 않았습니다. 이 안내를 메인·상세의 지도 위아래와 접근성 제목에 표시합니다.

`content.js` → 각 운영 숙소 → `map`에서 다음 값을 수정할 수 있습니다.

- `lat`, `lng`: 지도 중심의 위도·경도. 현재 값은 주변 지역 샘플 중심입니다.
- `search`: 네이버 지도 외부 링크에서 검색할 주변 역·관광지명. 숙소의 정확한 주소가 아닙니다.
- `label`: `[영어, 한국어, 중국어]` 지도 지역명.
- `kind: "area-sample"`: 현재 지도 성격. 이 값만 바꾼다고 정확한 위치 핀으로 전환되지는 않습니다.

공개 가능한 정확한 주소·좌표를 확정하면 `app.js`의 `syncNaverMap()`에서 마커 포함 여부를 반영하고 `copy.mapNotice`, `copy.mapSample`, `copy.mapTitleLabel`도 실제 안내에 맞게 교체하세요. 미확인 좌표를 숙소 주소로 표시하지 않도록 일부러 자동 핀을 넣지 않았습니다. `naverMapUrl()`은 외부 검색 링크만 생성합니다.

v12부터 네이버 지도만 사용합니다. SDK 로딩·인증 실패 시 로컬 안내 문구를 표시하고 네이버 지도 링크를 유지합니다. 다른 지도 서비스로 연결하거나 대체 지도를 불러오지 않습니다. 실제 중국 현지 네트워크에서의 지도 표시 여부는 확인하지 않았습니다. NAVER 계정 설정은 위 안내를 따릅니다.

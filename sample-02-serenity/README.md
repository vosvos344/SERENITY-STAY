# SERENITY STAY — 새 샘플

기존 루트와 독립된 HTML·CSS·JavaScript 사이트입니다. 패키지 설치와 빌드 과정 없이 사용할 수 있습니다.

## 미리 보기

이 폴더에서 `index.html`을 브라우저로 열면 기본 화면과 숙소 탐색이 동작합니다. 지도는 웹 주소에서 확인하세요.

프로젝트 루트에서 로컬 미리 보기를 실행하려면:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory sample-02-serenity
```

브라우저 주소: <http://127.0.0.1:4173>

## 현재 디자인과 인터랙션

- **대문:** 실제 숙소 이미지·영상을 화면 전체 너비로 보여줍니다. 큰 세리프 제목은 줄마다 시차를 두고 등장하며, 사진은 가로로 펼쳐지며 전환됩니다. 진행선·이전/다음·일시정지 버튼이 있습니다. 스크롤하면 대문의 여백, 이미지 확대, 문구 이동과 투명도가 함께 변합니다.
- **스크롤:** 소개 문장은 단어별로 드러나고, 아치형 공간 사진은 전체 너비로 펼쳐집니다. 디테일 사진 두 장, 큰 문구와 마지막 화살표도 스크롤에 반응합니다. 위로 되돌리면 같은 진행 상태로 복원됩니다.
- **숙소 탐색:** 한 번에 한 숙소를 넓게 보는 가로 갤러리. 카드 폭은 숙소 수와 독립적이며 화살표·터치·트랙패드·키보드로 탐색합니다. 이동할 때 다음 숙소 사진이 확대 상태에서 자연스럽게 제자리로 돌아옵니다.
- **부산:** 목록 상단에 눈에 띄는 오픈 예정 안내와 미리보기 버튼이 있고, 사진 중앙에도 큰 `COMING SOON` 문구를 넣었습니다. 카드 설명 영역에도 예약 전 상태를 표시합니다.
- **상세 창:** 큰 사진과 썸네일, 소개·침실·편의시설·이용 안내 탭으로 구성합니다. 침실별 침구, 식탁, 주방 기기, 세탁 시설, 체크인·아웃, 이용 수칙을 실제 공개 정보 기준으로 안내합니다. 데스크톱은 긴 본문만 얇은 스크롤로 읽고 예약 버튼은 본문 밖의 Grid 흐름에 둡니다. 모바일은 창 내부의 단일 세로 스크롤을 사용합니다.
- **지도:** 숙소 선택에 따라 해당 숙소의 위치·주소·네이버 지도 링크가 바뀝니다. 상세 창의 이용 안내에서 해당 숙소의 지도 영역으로 바로 이동합니다. 위치 미공개와 오픈 예정 상태를 구분합니다.

### 스크롤을 되돌릴 때

한 번 등장하고 `unobserve()` 하던 기존 처리를 삭제했습니다. 현재 화면 위치에서 매번 진행률을 계산하므로 같은 스크롤 위치로 돌아오면 같은 시각 상태로 복원됩니다. 글자 등장도 화면 아래로 빠져나가면 초기화되고 다시 접근하면 재생됩니다.

스크롤 효과는 하나의 `requestAnimationFrame` 갱신 함수에서 처리합니다. 별도 애니메이션 패키지를 추가하지 않았습니다. 일반적인 세로 스크롤을 가로 이동으로 바꾸거나 가로채지 않습니다. 위치 측정은 움직이지 않는 부모에서 하고 시각 이동은 자식에만 적용해 떨림을 피했습니다. `prefers-reduced-motion`이 활성화되면 내용은 완전히 보이고 스크롤 효과를 멈춥니다.

## 구현 내용

- 영어 기본, 중국어 간체·한국어 전환. 언어 선택만 브라우저에 저장합니다. `?lang=zh`, `?lang=ko`, `?lang=en` 링크도 지원합니다.
- Mia 201·202 실제 사진 및 상세 갤러리. 예약 버튼은 사용자가 제공한 각 Airbnb 링크를 새 탭에서 엽니다.
- 부산은 Coming Soon으로 표시하며 예약 버튼과 오픈 날짜를 만들지 않았습니다. 부산 카드는 숙소 실사진이 아닌 여행지 사진임을 명시했습니다.
- 배너 이미지 전환·부드러운 확대, 스크롤 등장, 사진 호버, FAQ 펼치기. 배너 일시정지와 `prefers-reduced-motion`을 지원합니다.
- 키보드 갤러리 이동, Esc 닫기, 상세 창의 기본 초점 제한과 닫은 뒤 초점 복귀는 브라우저의 `<dialog>` 기능을 사용합니다.
- 페이지 배치는 Grid·Flex로 구성했습니다. 대문과 공간 소개의 이미지·그라데이션·문구는 같은 Grid 칸에 겹칩니다. 상세 창의 오버레이는 브라우저 기본 dialog를 사용합니다. CSS `position:absolute`는 화면 낭독기 전용 문구와 건너뛰기 링크를 숨기는 접근성 처리에만 사용합니다. 고정 헤더·고정 예약 버튼은 없습니다.
- 사용하는 사진과 폰트를 로컬에 저장하여 구글 폰트 CDN에 의존하지 않습니다. 외부 연결이 필요한 기능은 Airbnb와 네이버 지도입니다.

## 메인 배너를 영상으로 바꾸기

영상 원본은 제공되지 않아 현재는 실제 숙소 사진 2장을 사용합니다. 무음 MP4 또는 WebM을 `assets/`에 넣고 `content.js`의 `hero`를 수정하세요.

```js
hero: {
  type: 'video',
  src: 'assets/hero.mp4',
  poster: 'assets/mia-201-02.jpg',
  // interval과 slides는 다시 이미지 방식으로 전환할 때 유지합니다.
}
```

영상은 무음·반복·인라인 재생됩니다. 자동 재생이 제한되면 재생 버튼을 사용합니다. 파일을 불러올 수 없으면 포스터 이미지로 복귀합니다. ‘동작 줄이기’가 활성화되어 있으면 자동 재생하지 않습니다. 탭이 숨겨지거나 상세 창이 열리면 재생을 멈춥니다.

## 숙소 추가

`content.js`의 `stays` 배열에 기존 숙소 객체를 복사하여 고유 `id`, 이름, 도시, 사진, 수용 인원, Airbnb 링크를 입력합니다. `headline`, `rooms`(제목·설명 키 쌍), `highlights`, `equipment`도 기존 숙소처럼 채워 상세 탭을 구성하세요. 설명과 사진 설명에 사용하는 키는 `copy.en`, `copy.zh`, `copy.ko`에 함께 추가합니다. 가로 목록과 상세 갤러리는 데이터에서 자동 생성됩니다. 숙소 개수만 늘려도 현재 순서·전체 개수·탐색 화살표의 상태가 자동 갱신됩니다. 숙소 카드의 폭은 개수와 무관합니다.

오픈 전 숙소는 `status: 'soon'`, `airbnb: null`로 두세요. 서울·부산 외 도시를 추가할 경우 해당 도시 번역과 `index.html`의 지역 필터도 추가할 수 있습니다. 숙소마다 `location`을 설정합니다. 새 숙소는 지도 선택 목록에도 자동으로 추가되며, 위치 데이터를 넣지 않으면 다른 숙소의 지도를 대신 표시하지 않습니다.

## 숙소별 네이버 지도

`map`에는 제공된 공개 Client ID만 공통으로 남겨두었습니다. 기존의 단일 미아역 좌표와 모든 숙소가 같은 동네라는 설명을 삭제했습니다. 주소·좌표·링크는 각각 `stays[].location`에서 관리합니다.

**현재 실제 데이터는 3곳 모두 `location: null`입니다.** 각 숙소의 정확한 주소 또는 네이버 지도 링크를 확인하기 전에는 임의 좌표를 넣지 않습니다. 서울 숙소는 해당 Airbnb의 위치 정보 링크를 제공하고, 부산은 위치 공개 예정으로 표시합니다.

숙소의 위치가 확인되면 다음 형식을 채웁니다. `null`을 실제 확인된 숫자 좌표로 교체하기 전까지는 지도를 표시하지 않습니다.

```js
location: {
  precision: 'exact', // 'area'는 정확한 주소가 아닌 대략적인 주변 지역
  latitude: null,
  longitude: null,
  address: '',       // 공개할 주소
  naverUrl: '',      // 이 숙소의 네이버 지도 링크
  // area: 'mia201Area',              // 선택: 지역명 번역 키
  // description: 'mia201AreaCopy',  // 선택: 숙소별 주변 설명 번역 키
}
```

- `exact`: 해당 좌표와 숙소명 표시. `area`: 대략적인 지역임을 명시하고 주변 650m 범위를 함께 표시합니다.
- `location: null` 또는 유효하지 않은 좌표: 이전 숙소의 지도·마커를 숨기고 현재 숙소 안내를 표시합니다.
- 주소·네이버 링크만 있고 좌표가 없는 경우: 주소와 외부 링크는 사용할 수 있으며 내장 지도는 대기 상태입니다.
- 지도 위의 숙소 선택, 이름·주소·링크, 상세 창 이용 안내는 같은 숙소 데이터를 사용합니다. 언어를 바꿔도 선택한 숙소가 유지됩니다.
- SDK와 지도 인스턴스는 하나만 사용하고, 선택에 따라 중심·마커·영역을 갱신합니다. SDK 로딩 중 선택을 바꿔도 마지막 선택이 적용됩니다.
- 인증·네트워크 오류·12초 시간 초과 시에도 선택한 숙소의 네이버 링크 또는 Airbnb 링크를 제공합니다. 위치가 없는 숙소를 대신 임의 지역에 표시하지 않습니다.

공식 JavaScript v3 SDK의 `ncpKeyId` 방식으로 로드합니다. 유효한 좌표가 있는 숙소를 선택하거나 해당 지도 영역에 가까워질 때 연결합니다. 공개 주소를 확인하지 못한 현재 데이터에서는 불필요한 SDK 연결을 하지 않습니다.

제공된 ID는 이전 미아역 주변 지도 검사에서 실제 타일 로딩을 확인했습니다. 숙소별 선택 검사는 브라우저 안에만 주입한 서로 다른 테스트 좌표로 진행합니다. 테스트 좌표와 주소는 실제 숙소 데이터나 미리보기에 저장하지 않습니다.

다른 도메인에서 인증 오류가 발생한다면 NAVER Cloud의 Dynamic Map 사용 여부와 등록한 Web 서비스 URL을 확인하세요. 로컬 주소는 `http://127.0.0.1:4173`입니다. 콘솔 설정과 공개 Client ID는 변경하지 않았습니다.

구현 API 참고: [Naver Map](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.Map.html), [Marker](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.Marker.html), [Circle](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.Circle.html).

## 검증

의존성 없이:

```sh
node sample-02-serenity/check.cjs
node --check sample-02-serenity/app.js
```

Playwright와 Chrome이 **이미 설치된** 환경에서는 로컬 미리 보기 실행 후:

```sh
node sample-02-serenity/check.cjs --browser
# 지도 변경만 검사
node sample-02-serenity/check.cjs --maps
```

별도 패키지 설치는 실행하지 않았습니다. 이 작업 환경에서는 번들에 포함된 Playwright와 설치된 Chrome을 사용했습니다.

확인 범위: 영어·중국어·한국어 × 1440/768/390/320px 가로 넘침, 숙소 필터, 두 Airbnb 목적지, 상세 탭·썸네일·침실 구성·키보드 이동·초점 복귀·얇은 스크롤·모바일 예약 버튼 접근, 모바일 메뉴, FAQ, 동작 줄이기, 지도 연결 실패 시 대체 링크, 영상 파일 오류 시 이미지 복귀. 추가로 대문·단어별 문구·공간 사진의 역방향 상태 복원, 자동 슬라이드와 일시정지를 검증했습니다. 상세 창은 3개 언어로 1280×600, 768×700, 320×740 화면에서도 가로 넘침과 예약 버튼 접근을 확인했습니다. 높이 720px 이하의 데스크톱에서는 제목·여백을 줄여 읽기 공간을 확보합니다. 1440px 화면에서 임시 숙소 3개와 12개 모두 카드 너비 1170px / 갤러리 높이 550px로 동일했습니다. 임시 데이터는 검사 브라우저 안에서만 사용하며 실제 콘텐츠에는 남기지 않았습니다. 실제 예약·결제는 실행하지 않았습니다. 지도 전용 검사는 숙소별 선택·상세창 연결·위치 미공개 전환·정확한 위치와 대략적 위치 전환·로딩 중 선택 변경·인증 오류·좌표 오류·12개 숙소 선택 목록을 확인합니다. 실제 네이버 SDK의 표시와 선택 전환도 브라우저 전용 테스트 좌표로 검사합니다. 실기기 Safari·Android Chrome과 실제 숙소 영상 재생은 추가 확인 대상입니다.
